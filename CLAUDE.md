# Logbook — Lifelive Motorsport

Pour tout ce qui concerne le nom, l'apparence, les couleurs ou les BU, suivre `docs/BRAND.md` (valeurs exactes : `docs/brand-kit/tokens.css` et `docs/brand-kit/bu.ts`, logos officiels : `frontend/brand/`).
L'entreprise s'écrit toujours « Lifelive » ou « Lifelive Motorsport ».

Application : FastAPI (`backend/`) + front en JavaScript sans framework (`frontend/`), hébergée sur Cloud Run ; tests : `cd backend && python -m pytest -q`.
Le cache du service worker (`frontend/sw.js`, constante `C`) se monte à chaque changement du front.

Navigation : 4 chapitres / 8 modules, définis dans `frontend/modules.js` (registre) ; chaque page a une clé « groupe/page » dans `MENU` (`frontend/app.js`) et, côté serveur, ses routes et données dans `backend/app/access.py` (`PAGES`) : ajouter une page ou un module = renseigner ces trois endroits. Les droits des utilisateurs se donnent page par page (Administrer › Équipage).

Langues : l'interface est en français (langue source) avec un bouton FR / EN en haut à droite. Les traductions sont dans `frontend/i18n-en.js` (texte français exact -> anglais ; motifs pour les phrases à valeurs variables) ; un texte absent du dictionnaire reste en français. Tout nouveau texte visible doit être ajouté au dictionnaire. Les formats de nombres suivent `LOCALE()`.

Planifier › Ressources (3 pages : Staff interne, Staff externe, Véhicules ; clés `planifier/res_staff`, `res_ext`, `res_veh`) : réservées au Super User (comme Administrer › Équipage, elle n'est jamais attribuable à une catégorie) ; le compte Google du staff est le champ `google_email` de sa fiche (`backend/app/staff.py`), les prestataires externes sont gardés dans `dashboard/resources` (`backend/app/resources.py`). L'accès à Google Workspace se fait par délégation à l'échelle du domaine (`backend/app/gauth.py`, variable `GOOGLE_DELEGATED_USER`).

Page Planifier › Événements (Super User) : les événements sont créés dans les agendas Google des BU (`backend/app/planning.py`, agendas de `CALENDAR_IDS`) ; Google Agenda reste la seule source de vérité (propriétés partagées `logbook`, `kind`, `lbid`). Lieu, kilomètres et alerte Suisse / Royaume-Uni : `backend/app/maps.py` (variable `GOOGLE_MAPS_API_KEY`, départ `LIFELIVE_ORIGIN`).

Planifier › Planning (`planifier/planning`, ouvert à tous les rôles et cochable par catégorie, lecture seule) : vues « Par ressource » et « Calendrier », semaine ou mois, détail au survol ; données de `GET /api/planning` (`backend/app/planning.py`, `planning_view`), qui n'expose ni adresses e-mail ni données de paie ; `frontend/planning.js`.

Consigner › Pointages (module à sous-menus : « Ma semaine » `consigner/timesheets`, « Équipe » `consigner/team`, cochables par catégorie ; droits fins côté serveur dans `backend/app/timesheets.py`, routes `/api/timesheets`, écran `frontend/timesheets.js`) : un pointage = une durée sur un job (atelier lié à un véhicule, événement, ou tâche de fond) ; le mécanicien (compte Google = `google_email` de sa fiche staff) le modifie 24 h, puis seul le chef d'atelier (rôle « Atelier » de la fiche staff, choisi dans Planifier › Ressources › Staff interne : Mécanicien, Chef d'atelier CARS, XC ou les deux ; indépendant du libellé de la fonction ; Super User = tout) ; le chef valide. Facturable = job lié à un véhicule ou un événement (axes Odoo CARS / MEETING). Données dans Firestore (`timesheet_jobs`, `timesheet_entries`), photos et mémos vocaux dans `STAFF_BUCKET` (préfixe `timesheets/`). Rien n'est encore écrit dans Odoo (phase 4).
Transcription des mémos vocaux (`backend/app/speech.py`) : le navigateur convertit le mémo en WAV 16 kHz mono, `POST /api/timesheets/transcribe` le transcrit par Google Speech-to-Text v2 (variables `SPEECH_MODEL` = chirp_2, `SPEECH_LOCATION` = europe-west4, `SPEECH_LANGUAGE`, `TRANSCRIBE=off` pour désactiver) et le texte pré-remplit l'intervention.
Conservation des pièces jointes des pointages : bucket dédié `TIMESHEETS_BUCKET` (repli sur `STAFF_BUCKET`) ; mémos vocaux 90 jours (le texte transcrit reste), photos 10 ans, heures et textes sans limite ; suppression par règles de cycle de vie du bucket (91 jours pour les fichiers audio, 3 660 jours pour les images).
Modèles de jobs et listes de contrôle (Pointages) : collection `timesheet_templates` (modèle de départ « Révision Circuit » dans `backend/app/ts_seed.py`, créé une seule fois) ; un job atelier reçoit une copie du modèle (`checklist`), le mécanicien coche les lignes faites dans son pointage (`lines`), « Fait / Par / Quand » se remplit tout seul ; le modèle d'une nature de job (Pre-event, Post-event, Autre) est proposé à la création du job.
Présence et alertes (`backend/app/presence.py`) : jours ouvrés d'après `work_days` de la fiche staff (lundi à vendredi par défaut, réglable dans Ressources › Staff interne), jours fériés belges, absences = congés approuvés et événements où la personne est invitée ; le pointage du jour est attendu à partir de 17 h (15 h le vendredi). `POST /api/cron/timesheet-alerts` (Cloud Scheduler, jeton OIDC de `CRON_SERVICE_ACCOUNT`, audience `CRON_AUDIENCE`) envoie un e-mail aux mécaniciens sans pointage (Gmail API, portée gmail.send, `PUBLIC_URL` pour le lien) ; le chef voit les manques dans le cockpit du jour (page Équipe).
Congés (`consigner/leaves`, `backend/app/leaves.py`, `frontend/leaves.js`) : types copiés de Fullyn (congés payés, compensation, extra-légal, récupération de jour férié, maladie, autre), demi-journées, justificatif obligatoire pour une maladie de plus d'un jour ; soldes saisis dans Coûts du personnel › Données source (`leave_alloc`) ; validation par le chef d'atelier pour les mécaniciens de son équipe (même BU), par le Managing Director (Super User) pour les chefs d'atelier et le reste du personnel ; un congé approuvé est créé dans l'agenda Google « warnings » (`LEAVE_CALENDAR_ID`, sinon recherché par son nom), visible dans le Planning, déduit des alertes de pointage ; écriture dans Odoo : phase 4.
